# V3.2.1 Preview-only installation and testing
This package is a local candidate. No live branch was created or deployment started. Use only after separate Preview authorization. Never merge Main or publish to icarecrm.dev without explicit approval.

1. Verify current non-production branch matches archived V3.2.0 baseline. Preserve original commit; export a full JSON backup from each working device with unsynchronized changes. JSON backups are unencrypted; secure them. Do not clear browser storage or reset passphrases.
2. In Cloudflare Pages settings check which branch is Production; keep it unchanged. Verify Preview resources are isolated from live Firebase/Cloudinary/reporting before any write or upload test. A Preview URL does not isolate the database. Do not overwrite existing encrypted settings.
3. In GitHub Desktop, create local branch `v3.2.1-mobile-preview` from verified V3.2.0 commit. Copy the files listed in PATCH_MANIFEST.txt into matching locations, using a single local commit. Only runtime UI file changed is public/index.html; package.json updates version and test command. No server-side files, schema or configuration should be replaced. Keep the actual working Pages project name and Wrangler settings.
4. In repository root with Node 22+, run `npm test` (87 passed, zero failed) and `node build-pages.mjs` (validated). Optional isolated Python Playwright Chromium tests: `python mobile-browser-smoke.py` and `python workspace-browser-smoke.py`; set CHROMIUM to your executable path. Tests do not use live client records.
5. Review changed files for unexpected modifications or credentials. Stop before Push origin/Publish branch until Preview deployment is explicitly authorized. Then push only the non-production branch; automatic Git-integrated Pages should create a Preview deployment if enabled. Verify Preview label, commit, branch and hostname. Build command stays `node build-pages.mjs`, output `public`, repository root. Do not change production branch, domain, secrets or rules. No new environment variables/bindings.
6. Open the stable branch preview URL on iPhone and computer; do not use the live domain. On isolated resources, verify sign-in with existing authorized test account and passphrase, refresh direct link, mobile hub, all eight primary icons and four secondary modules, Back/Forward and switching. At <=800px only the selected module is displayed; desktop retains sidebar. Verify iPhone safe areas, scroll, dark mode, enlarged text, VoiceOver and orientation. Test notes/forms attachments, calendar/progress, Training and Programs, CSV/XLSX/JSON backup, Cloudinary upload only with explicit consent and separate live write-test approval, sign-out lock and two-device sync. Confirm Production settings and records untouched. Existing reporting Worker compatibility issue is outside scope.
7. Rollback: revert only the Preview commit (or retry verified previous Preview deployment). There is no V3.2.1 data migration, but new edits made during testing are still records in the existing workspace: keep current backups and review before any restore. Do not reset device storage or restore a stale workspace over newer changes. If a preview fails, stop and preserve records.
